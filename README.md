# 🐧 Linux Storage Provisioning & File System Management
> Ubuntu 리눅스 서버 환경에서 스토리지를 직접 할당하고, 파티션 분할부터 파일 시스템 포맷 및 마운트까지 인프라 구축의 전 과정을 수행한 프로젝트입니다.

## 🎯 프로젝트 목적
단순히 클라우드 스토리지를 사용하는 것을 넘어, 리눅스 OS가 데이터를 저장하고 접근하는 구조적 방식을 깊이 이해하기 위해 진행했습니다.
디스크의 물리적 추가부터 운영체제의 디렉터리 구조에 연결하기까지의 파이프라인을 직접 구축하며 서버 인프라 관리 역량을 다졌습니다.

## 🛠️ Tech Stack
- OS: Ubuntu Linux
- File System: ext4
- Storage CLI: `fdisk`, `mkfs`, `mount`, `lsblk`, `df`, `du`

## 🏗️ Storage Provisioning Pipeline (3-Steps)
새로운 디스크를 리눅스 시스템에 안전하게 인식시키기 위해 다음 3단계를 거쳤습니다.

1. 파티션 설정 (fdisk): 하드 디스크(`/dev/sdb`)를 추가하고, `fdisk` 명령어를 통해 Linux 파티션(`/dev/sdb1`)을 안전하게 생성 및 저장했습니다.
2. 파일 시스템 포맷 (mkfs): 빠른 속도와 안정성을 제공하며 대용량 처리에 적합한 리눅스 기본 파일 시스템인 `ext4`를 채택하여, `mkfs.ext4` 명령어로 파티션을 포맷했습니다.
3. 디스크 마운트 (mount): 포맷된 디스크를 리눅스의 디렉터리 트리인 `/mnt/`에 연결(`mount`)하여 실제 데이터를 저장할 수 있는 공간으로 활성화했습니다.

## 🌟 인프라 관리 및 문제 해결 경험 (STAR 기법)
### [이슈] 파일 시스템 데이터 무결성 보장 및 안전한 장치 관리
- Situation (상황): 서버 운영 중 스토리지를 교체하거나 디렉터리 연결을 해제해야 할 때, 강제로 디스크를 제거할 경우 데이터 손상 및 파일 시스템 트랜잭션 에러가 발생할 위험이 존재함.
- Task (과제): 데이터 유실 없이 안전하게 스토리지를 분리하고, 디렉터리와 파일이 차지하는 디스크 공간을 정확히 모니터링할 수 있는 관리 체계 확립 필요.
- Action (행동): - `df -h` 명령어로 파일 시스템 단위의 남은 공간을 실시간 모니터링하고, `du -sh` 명령어로 특정 디렉터리가 실제로 차지하는 공간을 계산하여 리소스 낭비를 추적함.
  - 디스크 제거 전 반드시 `umount` 명령어를 통해 마운트된 파일 시스템의 연결을 논리적으로 해제하여 데이터 동기화를 보장함.
- Result (결과): 리눅스 스토리지 생태계와 블록 장치(`lsblk`)에 대한 높은 이해도를 갖추게 되었으며, 
                이 경험은 훗날 메인 프로젝트에서 메모리 부족(OOM) 현상 발생 시 하드 디스크를 활용해 스왑(Swap) 메모리 파티션을 구축하고 할당하는 트러블슈팅의 핵심 밑거름이 됨.
